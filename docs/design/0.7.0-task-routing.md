# Design: task routing, escalation and the routing report (0.7.0)

Status: approved for build (2026-11-11). Inspired by Databricks' Smart Routing
(task-aware routing from a medium model, labels from a small fast classifier,
subagents routed on their own, an evaluation loop on traces), adapted to a
client-side plugin that works with any provider.

## Goals
- Route per task, not per prompt: start on the medium model (Sonnet), commit a
  model once the task is clear, keep it to protect the prompt cache.
- When a later prompt needs a stronger model and switching would throw the
  cache away, escalate to an Opus subagent instead of staying under-powered.
- Give the working model an advisor-like way to ask a stronger model mid-task,
  on any gateway (Anthropic's server-side advisor tool is not available on
  every gateway).
- Measure: a report of the cost against an all-Opus baseline, and an export.

## Non-goals
- No change to `adaptive`, `every-turn`, `session-start` or `off` behaviour.
- No automatic spawning by NEXUS: the main model decides to delegate.
- No prompt text in the log, the report or the export.

## 1. Labels (all classifier steps)
Seven choice labels besides `route` and `difficulty`, asked in the same single
request (Jev: 9 questions in one SystemOne call, verified live 2026-11-11, 6 of 6
HTTP 200 in 0.30 to 0.47 s, no slower than 2 questions):

| Label | Values |
|---|---|
| `specified` | `clear` (the goal and target are stated), `vague` (an acknowledgement, a vague wish, or the goal is missing) |
| `scope` | `none`, `local`, `multi_file`, `cross_system` |
| `evidence` | `snippet`, `traceback`, `reference`, `none` |
| `failure` | `crash`, `wrong_behavior`, `performance`, `none` |
| `localization` | `pinpointed`, `likely_local`, `spread` |
| `language` | `python`, `typescript`, `sql`, `iac`, `shell`, `jvm`, `other` |
| `project` | `data`, `web`, `infra`, `tooling`, `docs`, `other` |

The Haiku and Ollama steps ask for the same labels in their JSON. A missing or
invalid label is left out (never guessed). Setting `labels` (true): false sends
only `route` and `difficulty`. Observed: `language` is unreliable; it feeds the
report only, never routing.

## 2. The `task` mode (new default `routeMainLoop`)
State per session: `committed` (a model) or not.

- **Clear prompt:** `specified=clear` with probability ≥ `minConfidence`, or
  `evidence` in {`snippet`, `traceback`}. Without labels, every classified
  prompt counts as clear (the mode then behaves like `adaptive` plus escalation).
- **Not committed:**
  - continuation or vague prompt: the model stays (the session model, Sonnet by
    default); logged `vague` (or `continuation`); nothing is committed. Amended
    in 0.7.2: this holds only while the context is within `switchMaxContext`
    (a larger conversation has its task; the classifier reads one prompt alone
    and calls follow-ups vague, observed live 2026-11-11), and after the commit
    `specified` blocks nothing.
  - clear prompt: the decision goes through the existing switch rule
    (`switchConfidence`, `switchMaxContext`, window guard). Whatever runs after
    it (switched, or kept) becomes the committed model; logged as today plus
    `committed: true` on the entry.
- **Committed:**
  - routed model lighter or equal: kept (the existing delegation hint for a
    lighter model stays, under `delegationHint`).
  - routed model heavier (tier haiku < sonnet < opus/fable) and the prompt is
    clear: if the context is ≤ `switchMaxContext`, switch and re-commit; otherwise
    **escalate**: keep the model and attach the escalation directive (below);
    logged `escalated`.
- **Cache lost anyway, commitment dropped** (logged `rerouted`, reason
  `clear`, `compact`, `resume` or `idle`): `/clear`, a compaction
  (`session.compact`), a resume, or no main-loop request for more than
  `cacheTtlMinutes` (default 5; 60 when the provider caches for an hour). The
  next clear prompt may switch with the `switchMaxContext` guard lifted for an
  `idle` or `compact` re-route (the cache is cold anyway); the window guard stays.

Escalation directive (hidden prompt context, one paragraph):
"NEXUS router: this request was classified <cell> (<conf>) and needs a stronger
model than <current>. Switching now would drop the <N>k-token cache. Delegate
the hard part to the `nexus:frontier` subagent (Agent tool, a self-contained
brief), then check and integrate its result. For a short second opinion
instead, call the `consult` tool."

## 3. Escalation layer (`hooks/escalate/`)
- **`nexus:frontier` agent type**, registered at `session.start` with
  `$.agent.register` when `escalation` is on: model = the profile's
  `reasoning.high` model (Opus), its own system prompt (work from the brief,
  verify, report what changed and what is uncertain). Description (what the
  model reads to decide): use it when stuck, before a risky or hard-to-reverse
  approach, before declaring hard work done, or when NEXUS asks to escalate.
  At spawn the router does not classify a `nexus:frontier` subagent: it keeps
  the Opus model and effort `high`, logged `escalated` on the new loop.
- **`consult` tool** (`mcp__nexus__consult`), registered with
  `$.tool.register`, not deferred: input `{ goal, tried, question, context? }`
  (the caller writes a brief; NEXUS adds nothing from the transcript). It calls
  `$.model.complete` on the same Opus model with effort `high` and returns the
  advice. Capped at `consultMax` calls per session (default 5, 0 = the tool is
  not registered); past the cap it answers a short refusal. Logged `consulted`
  with the advisor model; the brief text is never logged.

## 4. Usage, report and export (`hooks/router/report.ts`, `log.ts`)
- **Usage store** `router.usage` (in `$.store`): per session and model, the
  sums of input, output, cache-read and cache-write tokens and turns, from every
  `turn.complete` with usage (main loop and subagents), plus `consult` calls.
  Newest 50 sessions kept. Written only when `decisionLog` is on.
- **`/route report [n]`** (n sessions, default 10): per model the share of
  turns and tokens; the estimated cost with the HUD's price table (`prices`,
  `upliftPct`); the same tokens priced at Opus as the baseline and the saving in
  % and dollars; the counts of switched, escalated, consulted and rerouted. The
  baseline is labelled an estimate (another model would have used different
  tokens).
- **`/route log export [path]`**: JSONL, one line per log entry
  (`{"type":"decision",...}`) and per usage record (`{"type":"usage",...}`).
  Default path `./nexus-route-<YYYYMMDD-HHmm>.jsonl` in the session's working
  directory. No prompt text.

## 5. Settings
| Setting | Default | |
|---|---|---|
| `routeMainLoop` | `task` | new value `task`; the others unchanged |
| `labels` | `true` | send the label questions |
| `escalation` | `true` | register `nexus:frontier` and send the escalation directive |
| `consultMax` | `5` | consult calls per session; `0` = no tool |
| `cacheTtlMinutes` | `5` | idle gap after which the cache counts as cold |

## 6. Limits to state in the release
- The commit rule and the escalation directive are tested with the engine's
  test harness; whether the main model follows the directive is model
  behaviour, checked live only by `/route log` (`escalated` then a
  `nexus:frontier` spawn).
- The report's baseline is an estimate.
